# Implementation traps

These are the non-obvious behaviours that have caused bugs, silently broken
features, or hard-to-diagnose failures. Read the relevant section before
touching the backends, the scheduler, the runtime, or the input path.

## Backends

### ydotool absolute motion is not an absolute warp

`ydotool mousemove --absolute` is not a real absolute warp in ydotool 1.0.4.
It sends `REL_X/REL_Y = INT32_MIN` first (top-left), then applies the target as
relative deltas. Pointer acceleration turns that into a corner jump or a wrong
position. Measured on KWin: `--absolute 640 420` landed at `0,0`. Never use it
for `cursor warp`.

### `YdotoolBackend` owns a pointer backend

`YdotoolBackend` therefore uses its own `UInputBackend` absolute pointer lazily
for `warp`, `move`, and `scroll`, and keeps ydotoold for buttons, keys, and
text. If `/dev/uinput` is not writable, pointer motion fails with a clear error
instead of falling back to the top-left hack.

### Absolute axis ranges must be consistent

`UInputBackend` declares `ABS_X`/`ABS_Y` with `min = 0`, `max = width - 1`. The
kernel rejects inverted or inconsistent axis ranges with `EINVAL`. Axis info
goes through `UInputDevice` in `src/uinput.cpp`.

### Backend selection

`output = "auto"` uses ydotoold when the client and its socket exist, otherwise
`uinput` when `/dev/uinput` is writable, otherwise ydotoold again so its error
message can explain the missing daemon. `choose_backend()` in
`src/backends.cpp` is the only place that decides.

### ydotool socket discovery

`ydotool_socket_path()` (`src/subprocess.cpp`) checks `YDOTOOL_SOCKET`, then
`$XDG_RUNTIME_DIR/.ydotool_socket`, then `/tmp/.ydotool_socket`.

### Button encoding is ydotool's, not the kernel's

Buttons use ydotool's encoded values: ydotool's own button index
(`left = 0`, `right = 1`, ...) `| 0x40` for down, `| 0x80` for up — not the
kernel `BTN_*` code. Keys use `code:1` and `code:0`.
`tests/test_runtime.cpp` pins `click 0x40` / `click 0x80` for left.

### `type_text` must not be escaped twice

`type_text` through ydotool passes `-e 0 --`, because Loomwright already decoded
the `.loom` string. Letting ydotool escape again turns a literal backslash
before `n` into a newline.

### uinput pointer writes

The uinput pointer writes `ABS_X`/`ABS_Y` for warps and `REL_X`/`REL_Y` for
moves, then a `SYN_REPORT`. Coordinates are clamped to `0..width-1` and
`0..height-1`.

### The uinput text mapper is US layout only

Add new shifted symbols to both the shifted set and the shifted map, and new
plain symbols to the plain set (`src/backends.cpp`). Non-US layouts and Unicode
should go through ydotool instead.

### Key code lookup

Key code lookup uses the tables in `src/keys.inc` (generated by
`scripts/gen-keytable.sh` from the kernel `input-event-codes.h`). Some kernel
codes map to lists of aliases; `canonical_key_name` upper-cases and resolves
aliases.

### Injected devices must be ignored

`Runtime::open_input_devices()` drops names containing `loomwright`, `ydotool`,
`virtual pointer`, or `remap_clicks`, keeps keyboards (both `KEY_A` and
`KEY_ENTER`/`KEY_SPACE`) always, and keeps mice only when the script binds a
mouse button. Mice are observed in coexistence mode: they are never grabbed, so
the physical click still reaches applications and a `when mouse ...` block can
add a modifier but cannot replace or suppress the click.

### Do not advertise tablet buttons

`uinput_key_capabilities()` in `src/backends.cpp` builds the advertised key
set. It deliberately skips the `BTN_MISC..KEY_OK-1` block and adds back only
the pointer buttons. Declaring `BTN_TOOL_PEN`/`BTN_STYLUS` (which a naive
`0..KEY_MAX` sweep does) makes udev tag the device `ID_INPUT_TABLET=1`, and
libinput then ignores its pointer and keyboard events entirely — warps, clicks,
scrolling and typing all silently do nothing. Check classification with
`udevadm info -q property -p /sys/class/input/eventN | grep ID_INPUT` while a
script runs.

### Wait for udev and libinput before the first output

`UInputDevice` waits for udev to write `/run/udev/data/+input:<sysname>` and
then for libinput to open the node before returning. Without that wait, the
first `cursor warp` after startup is folded into the device's initial ABS state
and never arrives as motion, and a replayed key can be swallowed. Keep the
device open for the whole run (created once, not per action).

## Input and passthrough

### Key consumption grabs and replays

Key consumption grabs the physical device with `EVIOCGRAB` (`src/input.cpp`)
and replays non-consumed events through a passthrough uinput device. The
passthrough mirrors `EV_KEY`, `EV_REL`, `EV_ABS`, and `EV_MSC` but
deliberately not `EV_REP`, otherwise held keys would repeat twice. `consume`
declarations are collected before devices are grabbed so the first key-down is
swallowed, and the panic key is removed from the consumed set.

### Grab only an idle device

`grab_idle_input` checks that the device is idle, drains old events, checks
idle again, grabs, and aborts if events appeared during the handoff. A press
just before the grab can still have its release intercepted; the error
identifies observed releases without injecting replacements. Physically tap
and release the key if it appears stuck.

### evdev overflow recovery

On `SYN_DROPPED`, discard through `SYN_REPORT`, take the kernel snapshot with
`EVIOCGKEY`, and reconcile. The whole read batch after resynchronization is
discarded because that tail predates the snapshot. A failed snapshot stops the
runtime rather than continuing with unreliable key state. Lost individual
transitions and relative motion cannot be recovered.

## Runtime

### Mouse holds are reference-counted by owner token

The default token is `default:<event_key>:<button>`. Use explicit `as TOKEN`
when two keys can hold the same button. Releasing one owner must not release
the physical button until the last owner frees it. `hold_button`/`hold_key`
mutate tracking only after a successful backend acquire, so a logical hold can
never exist without a physical one.

### Key presses are observed, not suppressed

`pressed_keys_` is global across devices; `device_down_` tracks per-device
state so the up edge fires only after the last device releases the key.

### Held timers favour a fixed cadence

Held timers live in `held_tasks_`, keyed by `(key, line)`. Each
`stays held every` tick is scheduled from the previous deadline, not from when
the handler returned, and overruns skip whole ticks instead of bursting (see
`Runtime::held_loop`). Held tasks are cancelled on key-up and device
disconnect.

### Cancellation must wake the suspended frame

A task sitting in `co_await child()` cannot be resumed directly: its resume
point is the await expression, so resuming it destroys the child frame while
the grandchild chain is still running, and the grandchild later returns into
freed memory. `Task::promise_type` tracks `parent`/`child`; `Scheduler::cancel`
marks the whole chain and resumes its deepest frame so each awaiter unwinds
with `TaskCancelled`.

### Dispatch runs as tasks

Dispatch runs as tasks spawned onto the scheduler
(`Runtime::spawn_background`). `event_key`/`event_edge` are carried in an
`EventContext` struct passed through `execute()`, not globals or TLS.

### Coroutine stack growth

A finished frame hands its awaiter back to the scheduler
(`Scheduler::defer_resume`) instead of resuming it inline. Resuming inline
would nest one native frame per await, and a script that awaits once per loop
iteration would overflow the stack. Only the scheduler's own loop may resume a
frame, so `Scheduler::resume_frame` is the single place a frame runs;
`Scheduler::drain_deferred` resumes the frames that were handed back. The
regression test is `repeated_awaits_do_not_grow_the_native_stack`.

### Loop caps and stop state

`repeat` and `while` cap at `kMaxLoop = 10000`. A panic key or Ctrl+C sets the
stop event; the CLI runs the scheduler and rethrows `runtime.failure()` after
the loop ends.

### Teardown releases everything

`Runtime` releases every held button and key and closes the backend on teardown
(`~Runtime`/`release_all_holds`). Keep `close()` defensive and idempotent.

### Cursor glide does not query the pointer

`cursor glide` starts from Loomwright's last known cursor position, or the screen
center. It does not query the real pointer.

### The panic key wins

The panic key is checked before regular bindings, so a script binding to the
panic key is unreachable. The checker warns about that.

## GUI and picker

- Native Wayland panels run GTK3 in an isolated helper process per panel. GTK
  exits on a broken Wayland connection, so it must not run in the automation
  process: the socket EOF instead stops the scheduler and releases holds. The
  child closes inherited input/output descriptors and exits with its parent.
  The helper drains GTK in bounded batches; the scheduler waits on its socket.
  `auto` prefers native Wayland in a Wayland session and falls back to X11;
  explicit selections never fall back.
- `GuiHost` uses XCB rather than Xlib. libX11 treats `_XIOError` as fatal and a
  preflight `poll` cannot protect an Xlib call against a later disconnect, so
  the panel uses explicit connection error inspection and no process-wide X
  error handler. See `src/xcb_connection.cpp`.
- `GuiHost` refreshes cached keysyms on `XCB_MAPPING_NOTIFY` so runtime layout
  switches (`setxkbmap`) are not ignored.
- `--get-mouse-pos` shows an **opaque, managed** full-screen splash window. An
  override-redirect or transparent window does not capture clicks over native
  Wayland windows. See [cli.md](cli.md#mouse-position-picker).

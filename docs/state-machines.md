## GUI connection-loss investigation

libX11 treats `_XIOError` as fatal. A preflight `poll` cannot protect an Xlib call against a disconnect that occurs after the check, and a non-local jump out of Xlib would skip C++ cleanup and may leave library locks held. The panel now uses XCB rather than Xlib, with no process-wide X error handler.

`src/xcb_connection.cpp` provides an RAII XCB transport with explicit connection error inspection and idempotent close. The integration test stops its private X server, kills it with an XCB reply pending and a production `GuiHost` starting up, and checks both error reporting and fd cleanup. The separate mouse-position picker also uses this transport; its integration test kills its private X server while the picker is issuing requests.
